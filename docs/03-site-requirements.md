# 03 站点需求

## 页面结构

| 路由 | 页面 | 内容 |
|---|---|---|
| `/` | 首页 | hero（定位语 + 搜索框）+ 统计行（条目总数 / 分类数 / **最近同步时间**）+ 57 个分类卡片网格 |
| `/docs/[category]` | 分类页 | 该分类下全部条目，列表行卡片，页内可筛选 |
| `/entry/[id]` | 条目详情页 | 服务名、官网链接、双语描述（中文优先、英文可展开）、分类标签、回链上游原文 |
| `/about` | 关于页 | 数据来源、同步机制说明、翻译免责声明、上游链接 |

## 功能需求

- **FR-1 双语展示**：所有条目中文描述为主，英文原文可展开对照；详情页双語并排。语言本身不做切换（UI 固定中文，内容双语）。
- **FR-2 搜索**：单套体系。⌘K 命令面板（cmdk + Fuse.js，客户端模糊匹配约 1,340 条自建索引，由 entries.json 生成、字段裁剪控制体积），首页与分类页均可唤起；分类页"页内筛选"为纯客户端过滤，不另建索引。Fumadocs 内置静态搜索不启用（静态导出下索引需全量下载，见 04 说明）。
- **FR-3 深色模式**：next-themes，默认跟随系统，可手动切换，无闪白（SSR 注入 script）。
- **FR-4 数据新鲜度可见**：首页统计行固定展示"最近同步时间"，关于页展示上游 commit sha——这类站点用户最大的不信任是"数据是不是死的"。
- **FR-5 外链安全**：所有外部链接 `rel="noopener noreferrer"`，新标签打开。
- **FR-6 条目降级**：翻译失败/被跳过的条目展示英文原文并标注"未翻译"，不留空白。

## 视觉要求（核心验收项）

- **字体**：中文正文用系统栈（PingFang SC / HarmonyOS Sans / Microsoft YaHei），不做全站中文字体包；拉丁文与数字用 `next/font` 的 Geist 或 Inter；hero 大标题可引入得意黑（Smiley Sans）或文楷（LXGW WenKai）的 CDN 子集制造记忆点，仅限标题，正文保持系统栈。
- **配色**：Fumadocs 默认中性灰打底，品牌色 Emerald 绿（"免费"的语义直觉）或 Violet；浅色/深色两套都手工校准，禁止纯黑纯白大色块。
- **条目列表行**：网站图标 + 服务名 + 一句话描述 + 分类标签。图标兜底策略：Google favicon 服务国内不可达，用"域名首字母 + 名称哈希取色"的 letter avatar 兜底，真实图标 `onerror` 自动降级，国内外访问均不破版。
- **微交互**：列表行 hover 轻微位移与底色变化；复制链接按钮；外链图标。克制，不做无功能动画。
- **响应式**：移动优先，375px 起步无横向滚动；命令面板移动端全屏化。

## 非功能需求

- **NFR-1 性能**：首屏 LCP < 2.5s（4G 模拟）；条目索引压缩后 < 300KB，客户端搜索零请求。
- **NFR-2 SEO**：全部页面静态生成；`sitemap.xml`；分类页与详情页独立 OG 元信息（静态生成，不上动态 OG 服务）。
- **NFR-3 可访问性**：语义化标签、键盘可达、对比度 WCAG AA。
- **NFR-4 构建时间**：约 1,500 个详情页 + 57 个分类页全量静态生成，Cloudflare Workers 构建控制在 5 分钟内（超出则详情页改按需生成）。

## 验收标准

- [ ] 移动端 375px 与桌面 1440px 下首页、分类页、详情页无布局破损。
- [ ] ⌘K 搜索输入"数据库"能召回相关条目且响应 < 100ms。
- [ ] 断网 favicon 的场景下图标降级为 letter avatar，无破图。
- [ ] Lighthouse 性能与可访问性均 ≥ 90。
- [ ] 深色模式下无纯黑纯白大色块，文字对比度达标。
